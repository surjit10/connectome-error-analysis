# FlyWire Research Framework – Prompt Library Reference

## Overall Goal

This repository is **not** being built to solve only one experiment.

It is being built as a **reusable research framework** capable of executing many biological error models, graph analyses, and future experiments with minimal code changes.

The philosophy is:

```
Framework

↓

Research Module

↓

Future Research
```

Once the framework is stable, future work should primarily involve **adding** new modules rather than **modifying** existing ones.

# Things to Be Careful About

* Never mix framework logic with biological logic.
* Never hardcode dataset-specific behavior outside the Data Loader.
* The Graph Object is the central contract—keep it stable.
* Prefer extending the framework by adding modules rather than modifying existing ones.
* Keep every component focused on a single responsibility.
* Document uncertainties instead of making assumptions when architecture or methodology is incomplete.

This is the reference I would keep open while implementing. It answers three questions before every prompt:

1. **What is this component responsible for?**
2. **What information do I need before implementing it?**
3. **Who depends on this component later?**

That makes it much easier to implement the framework incrementally without accidentally introducing unnecessary coupling or redesigning core components.
