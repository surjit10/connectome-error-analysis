## 2. Test Coverage

*   **ConfigManager:** Validates YAML loading, deep merge sequence (`defaults` → `dataset` → `error_model` → `analysis` → `experiment`), missing file fallback, schema compliance, and verifies `FrozenConfig` immutability by asserting that an assignment throws a `TypeError`.
*   **Dataset Registry:** Tests that synthetic datasets are registered via YAML definitions, that paths resolve successfully, and that querying non-existent datasets throws a `DatasetRegistryError`.
*   **Data Loader:** Proves the data loader returns a strict `FlyWireDataset` backed by Polars, accurately inferring types. It artificially corrupts the dataset schema requirements and tests that a `DataLoaderError` is properly raised.
*   **Graph Builder:** Validates that `igraph.Graph` objects are created cleanly from the `FlyWireDataset` without mutating the dataframes, retaining baseline weights (`syn_count`) and generating necessary lookups.
*   **Preprocessing:** Proves that passing the raw graph into `preprocess_graph` returns a `PreparedGraph` housing the graph by reference (not a copy) and generating the standard 7 structural features exactly once (`indegree`, `outdegree`, `total_degree`, `pagerank`, `reciprocal_ratio`, `hub_neighbor_count`, `two_hop_size`).
*   **Analysis/Error Registries:** Asserts that registrations map correctly by the `NAME` constant, duplicate registrations throw `RegistryError`, and dummy implementations correctly resolve input interfaces to `SUCCESS` status results.
*   **Experiment Runner:** Instantiates the runner with dummy registries and runs an `ExperimentConfig`, proving that the execution gracefully hands over inputs across the architecture and catches any subsystem output natively.
*   **Statistics & Export:** Ensures that running a successful pipeline writes `metadata.json`, `summary.csv`, `trial_results.csv`, and `config_snapshot.yaml` accurately in the output directory.
*   **Full Pipeline:** Runs a complete end-to-end simulation from YAML loading up to final file export on a small synthetic setup, guaranteeing execution stability.

## 3. Framework Validation

Every single phase (002–010) passes its corresponding unit and integration tests successfully.
During testing, minor bug fixes were made to the dummy modules to match strictly enforced abstract methods (such as `_perturb` instead of `_run` in `BaseErrorModel`), but **no functional code inside the core framework was altered or modified to satisfy testing**.
